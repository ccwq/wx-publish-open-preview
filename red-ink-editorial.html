RED INK EDITORIAL

工具的价值不在功能列表，在省下的判断成本

赤墨编辑完整正文样张 · 文中数字均为示例口径，非真实测评

选工具的时候，多数人先看功能清单，再比价格。真正决定使用成本的，往往不是这两样，而是每一次操作前后的判断开销：要不要用它、选哪一档、出了问题找谁。

这篇样稿把赤墨主题跑一遍完整正文：从问题定义、数据对照，到上手命令和适用边界。版式纪律只有一条——#D52B2B 这一种红，只出现在值得强调的语义位上。

01 / WHERE COST LIVES

判断成本藏在哪

一个功能再多的工具，如果每次使用前都要重新理解一遍规则，它的真实成本就被系统性低估了。判断成本通常出现在三个位置：

01选择成本：打开工具时要在多个档位之间反复比较，选错还要重来一遍。

02语义成本：输出结果需要二次翻译，才能交给下一个人或下一个流程。

03修复成本：出错之后没有明确的回退路径，只能整段推翻重做。

好的工具设计，是把这三种成本一个一个从流程里删掉，而不是用更长的功能清单把它们藏得更深。

03 / MINIMAL RUN

跑通一条最小链路

上手只涉及两个动作：切主题、渲染样稿。主题参数用 --theme 指定，输出目录由 --out 接住。深色章节内的正文用降级灰白，行内代码 token 换提亮红变体——强调红在近黑底不达 4.5:1 对比度，只保留给眉标装饰位。

bash

npm run render -- --theme red-ink-editorial \

  --out ./preview/red-ink

open ./preview/red-ink/index.html

跑通之后再谈调整：先确认字号和红线位置，再动配色。顺序反过来，调参时间通常翻倍。

04 / BOUNDARY

什么时候不该用它

单一强调红的前提，是全文只有一个值得强调的语义位。如果文章需要同时区分成功、警告、错误三种状态，这套纪律会反过来制造噪音——那时候该换主题，而不是往这里塞颜色。

重点

不含价格、数字或代码的文章同样成立：只保留眉标、正文、红线提示与小标题即可成篇。

版式是约束出来的，不是堆出来的。能删掉的强调位，就删掉。
